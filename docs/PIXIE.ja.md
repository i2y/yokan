# pixie

Rust を経由してコンパイルされ、GPU エンジン(gpui)で描画される GUI
第一の汎用プログラミング言語です。リアクティブなクラスと宣言的な view を
書くと、pixie は借用検査を必ず通る形の Rust を生成します — つまり Rust
コンパイラが全生成プログラムの第二の検証器として働きます。標準ライブラリは
薄い `.rpi` 型バインディングを介した Rust の crate エコシステムです。

```ruby
store Session {
  state name : String = ""
  state saved : Bool = false

  fn update(t: String) {
    name = t
  }

  async fn save {
    await Fs.writeString("/tmp/pixie-hello.txt", name)
    saved = true
  }
}

view Main {
  Column {
    TextField {
      text: Session.name
      placeholder: "your name"
      onTextChanged: Session.update(text)
    }
    Button { text: "save"; onClick: Session.save() }
    if Session.saved {
      Text { text: "saved: #{Session.name}" }
    }
  }
}
```

入力は IME 対応の本物のテキストフィールドに落ち、`await` はファイル
書き込みをワーカースレッドへ送って UI ループに再入し、store が変われば
`if` の行が現れます — 上のコードは全行、今日そのままコンパイル・実行
できます(`std::fs::write` への 2 行の `.rpi` バインディング `Fs` 付き)。

**はじめての方は[言語ツアー](TOUR.ja.md)へ** — 基本文法、
型システム、メモリ管理(何が回収され、何が回収されないか)、
コンポーネント、アニメーション、アクセシビリティ、パッケージング、
二層実行の仕組みまで、図解付きで一周できます。

## クイックスタート

```sh
cargo run -q -p pixie-cli -- install-runtime          # マシンごとに一度
cargo run -q -p pixie-cli -- build examples/counter/counter.pix --run
```

ほかの動詞: `check` · `test`(TAP)· `fmt` · `watch` — view 本体の編集は
実行中のウィンドウに**プロセス内・約 1 ミリ秒**でホットリロードされ
(状態保持)、それ以外は約 0.5 秒で再ビルド+再起動します。
`build --release` は AOT 専用バイナリを出力します: ホットリロード
機構とインタプリタは crate グラフごと剥がれ(counter デモで
60 MB → 13 MB)、挙動はバイト単位で同一です。

ビルドしたアプリはすべてヘッドレスでスクリプト実行できます:
`PIXIE_SCRIPT="input:Ada,click:save"` で操作を再生してエレメントツリーを
出力し、`PIXIE_TIER=interp` は同じスクリプトをホットリロード用
インタプリタで再実行します — 両者の出力はバイト単位で一致しなければ
ならず、これがこのプロジェクト常設の分岐ゲートです。

## エディタ対応

`extensions/vscode-pixie` は VS Code に**入力中のエラー表示・hover・
定義ジャンプ・補完**を提供します。エラーはコンパイラ自身の診断で、
「もしかして」の候補もそのまま出ます。加えて `.pix` / `.rpi` の色付けが
あり、ウィジェットカタログ、エレメントのプロパティ、スタイル、
`#{}` 補間、後置戻り値型やエラーユニオンに専用のスコープを当てます。

まずサーバを1度ビルドし、拡張を開発モードで入れます。

```sh
cargo build --release -p pixie-lsp
```


```sh
ln -sfn "$(pwd)/extensions/vscode-pixie" ~/.vscode/extensions/pixie-language-dev
```

を実行してウィンドウをリロードするだけです。拡張は開いている
ワークスペースの `target/` からサーバを探すので、チェックアウトなら
設定は要りません。インストール済みのものを使うときは `pixie.lsp.path`
を設定してください。Cursor / VSCodium / Windsurf はそれぞれ自分の拡張
ディレクトリを読むので、同じシンボリックリンクがそのまま使えます。
パッケージ化と文法の回帰チェックは拡張側の README にあります。

`pixie-lsp` は素の stdio サーバなので、LSP クライアントを持つ
エディタなら何でも使えます。

## 現状

初期段階ですが実物です。今日動くもの:

- **ウィジェット** — cute_ui から移植した全 17 エレメント:
  Column / Row / Stack / Text / Button / TextField(IME・選択・Tab
  リング)/ ListView / ScrollView / HScrollView / Image / Svg /
  DataTable / Modal / BarChart / LineChart / ProgressBar / Spinner。
  加えて `if` による条件レンダリングと `for` リピータ。移植元には
  なかった 18 番目として `Grid` があります(均等トラックと、任意の
  要素に書ける `colSpan:` / `rowSpan:`)。再利用可能な
  **コンポーネント**は view そのものです。既定値付きのパラメータ、
  インスタンスごとの `state`、`Slot { }` による子要素を持ち、
  行ごとの状態はリピータの深さを問いません(ネストした `for` も
  仮想化リストの中も含みます)。リピータは求めれば行の位置も
  束ねます(`for row, i in xs`)。
- **アニメーション** — 「この更新をアニメーションさせる」という
  囲みではなく、値が動く要素そのものに宣言します。`animate: 200.0` と `easing:`、それに `enter:` / `exit:` の
  フェード。補間は描画側ではなく要素ツリー上で走るので、
  ヘッドレス実行からも見えます。
  `PIXIE_SCRIPT="click:go,advance:100"` は、その瞬間に描かれる
  1フレームをそのまま出力します。
- **アクセシビリティ** — 役割・名前・値はカタログ全体で**導出**されるので、
  ツリーの大半は何も書く必要がありません。導出できないもの
  (見出し、アイコンの代替テキスト、名前付きツールバー)だけを
  `role:` と `label:` で補います。レイアウト用のコンテナは
  「グループ、グループ、グループ」と読み上げさせるより黙ります。
  ツリーは検証済みの出力です。`PIXIE_SCRIPT="a11y"` で出力でき、
  ウィンドウ側も同じ導出から AccessKit に渡します。
- **スタイルとテーマ** — 名前付きプロパティ集合(`style Key {
  background: "#313244" }`)。`+` でマージし、任意のエレメントに
  `style: Key` で適用、コンパイル時に完全インライン。`pub style` で
  モジュール間共有、`hover.background:`/`active.background:` で
  ボタン状態も装飾。色はセマンティックなテーマトークン("accent"、
  "panel")も書け、ダーク/ライトテーマに追従します。`theme:` は
  パレットを部分木に限定するので、暗いウィンドウの中に明るいパネルを
  置けます。値は式なので、アプリは自分のテーマをふつうの状態として
  持ち、切替ボタンを提供できます。その要素に `animate:` を付ければ、
  テーマ切替はクロスフェードになります。スタイルの編集は view 本体と
  同じく実行中のウィンドウに約 1 ミリ秒でホットリロードされます。
- **本当に遅延する仮想化リスト** — 10 万行のリストで、毎フレーム
  構築されるのは可視の約 14 行だけ。
- **async と HTTP** — `async fn` + バインディング呼び出しへの
  `await`。ブロッキング処理は gpui のスレッドプールへ、実行
  セマンティクスはウィンドウ/ヘッドレスで一つ。組み込み HTTP
  クライアントがその上に乗ります(`await Http.get(url)` /
  `getBytes` → `Bytes` / `post` / `Map<String, String>` ヘッダ付き
  `getWith`)。
- **ホットリロード** — 実行中のバイナリが自分の view 本体を再パースし、
  生きた World に対して再構築。`pixie watch` は保存ごとに
  プロセス内リロードか完全再ビルドかを判定します。
- **バインディング** — Rust crate への `.rpi` ファイルと、rustdoc JSON
  から `.rpi` を導出する `rpi-gen`(実物の `std.json` で計測済み:
  `std::fs` は 14 関数を束縛、束縛不能なものは理由付きでスキップ)。
  `Option<T>` は `T?` としてバインディングを渡り、ユーザー関数も
  `T?` を取り・返し・`nil` を書けます(`when some(v)` / `when nil`
  で消費)。`Vec<u8>` は COW の `Bytes` 値として渡るので
  `std::fs::read` は Int のリストではなくバイト列で返ります。
  C ライクな Rust の `enum` と `struct` も渡ります。
  タプル struct も渡ります。
  rpi-gen がバリアント単位、フィールド単位の対応を書いた宣言を出力し、
  フィールドは書き戻す先の Rust の型を名乗れます。
  対応を付けられないもの(ペイロード付きバリアント、非公開フィールド)は
  黙って壊れずに名前付きのエラーになります。
- **プロジェクトとパッケージ** — `pixie.toml` の `[crates]` テーブルに
  Rust crate を書くと、pixie が `.rpi` バインディング表面を自動導出
  (rustdoc JSON → rpi-gen、バージョンキー付きでコミット可能な
  キャッシュ)。バージョン解決は cargo 自身が担当。`[dependencies]`
  は pixie パッケージを path / git / レジストリインデックス経由の
  バージョン指定で取り込み、`pixie.lock` がリビジョンを固定
  (ロック済み依存は完全オフライン解決)。パッケージの顔は
  `src/lib.pix`(`pub use` で再エクスポート)。モジュールは
  エイリアス(`use foo as F`)・リネーム付き選択インポート
  (`use foo.{X as A}`)・ネスト(`use ui.buttons`)に対応し、
  モジュール間の同名アイテムは共存できます。プロジェクト
  ディレクトリの `pixie build` は `src/main.pix` をビルドします。
- **書かなくてよいメモリ管理** — オブジェクトは自動参照カウント(ARC)、
  値は COW。手で解放するものはなく、裏でヒープを走査するものもなく、
  借用検査も表に出てきません。
  メソッドが作ってどこにも渡さなかったオブジェクトは、
  スコープの終わりで回収されます(外に出ないことをコンパイル時に
  証明します)。store や別のオブジェクトが**保持している**ものは、
  最後の参照が消えた時点で、持っていたものごと解放されます。
  解放は最後の参照が消えたその場で起きるので、停止時間はありません。
  例外は閉路で、`weak` で断ち切れます。
  値(`String` / `List` / `Map` / `Bytes` / `struct`)は COW で、
  そもそもオブジェクトストアに入りません。
- **オブジェクトがオブジェクトを指す** — class 型のフィールドは参照を
  持つので、2つの持ち主が同じ1つのオブジェクトを指し、
  どちらから書いてももう一方に見えます。値の入れ子も自由で、
  木も再帰も書けます。
- **速度** — 値の処理は同じ Rust にコンパイルされ、同じ速度で走ります
  (実測: 算術ループ 1 反復あたり 0.19 ns、手書き Rust は 0.13 ns。
  どちらもサブナノ秒)。オブジェクトのプロパティの読み書きは約 3 ns で、
  素の struct フィールドのおよそ 3.5 倍です。これがダングリングしない
  参照と、変化を検知するリアクティブループの値段です。
  ベンチマークはツリーに入っています。
- **trait** — 振る舞いを1度宣言し、好きなだけ多くの型に実装し、
  そのすべてを受け取る関数を1つ書けます。`class` と `struct` が
  同じ trait を実装でき、呼び出しごとに専用版が生成されるので、
  この抽象化に実行時コストはありません。
- **値レイヤ** — ジェネリクス一式: trait 境界付き関数/メソッド、
  ジェネリック struct(`Pair(1, 2)` は推論)、`init` コンストラクタ
  付きジェネリッククラス(`Basket<String>()`)— すべて本物の
  Rust ジェネリクスへコンパイルされ rustc が単相化。加えて
  リテラル付き `Map<K, V>`、`List<T>`、`Bytes`、`nil` を持つ `T?`、
  `try`/`case` のエラー enum、複合代入演算子一式。
- **エンジン** — Zed ツリーの gpui を固定リビジョンで使用。macOS の
  入力メソッドコールバックにパニック封じ込めパッチを当てた
  `gpui_macos` を vendor 済み。

ツールチェインは `rust-toolchain.toml` で自己固定。約 500 の
ワークスペーステストと 31 デモの二層ゲートが緑です。ゲートは 58 本の
スクリプト読みを両方の実行ティアで再生し、1バイトでも差があれば
失敗します。アクセシビリティツリー、アニメーション途中のフレーム、
生存オブジェクト数も対象です。
上記の各機能の実行可能デモは `examples/` にあります。
