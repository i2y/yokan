# 型

**型は境界に書きます。**
**関数の中では推論されます。**
**どちらでも決まらないときは、ビルドが断って、代わりに何を書けばよいかを言います。**

規則はこれだけです。
以下は「境界」がどこを指すか、推論がどこまで届くか、三つの検査がそれぞれ何に答えるかの話です。

## どこに書くか

境界とは、値が作られた関数より長く生きる場所か、方言の外に出る場所です。

| 境界 | 書き方 |
|---|---|
| モジュールの state | `count: State[int] = State(0)` |
| store と model のフィールド | `total: int = 0` |
| 値クラスのフィールド | `x: float` |
| ヘルパーの引数と戻り値 | `def area_of(s: Shape) -> float:` |
| コンポーネントの引数 | `def card(title: str, n: int):` |
| `@py` の署名 | 引数すべてと戻り値 |

理由はどれも同じです。
コンパイルされた側はアプリが動き出す前に値をメモリ上に配置するので、最初の一行が走る前に形が決まっている必要があります。
`State[int]` は機械の整数を入れるセルであって、後から中身を見て決める箱ではありません。

## どこで推論されるか

ローカル変数の型は、代入されたものから決まります。
次のコードに注釈は一つもありませんが、型はすべて決まっています。

```python
def restock():
    n = count()                 # int   count が State[int] なので
    label = f"{n} left"         # str   f 文字列は str
    names = items()             # list[str]
    first = names[0]            # str   list[str] の要素
    total = n * 2 + 1           # int   int どうしの算術
```

推論は局所的で、当て推量をしません。
右辺が自分の型を持たないときは、こちらが書きます。

```python
out: list[str] = []             # 空のリストには要素型がない
```

関数の中で書く注釈は、たいていこの形です。
空から始まる入れ物です。

## 型の語彙

| 型 | 補足 |
|---|---|
| `int` `float` `str` `bool` | 機械の整数と倍精度浮動小数点数。`str` は Python のもの |
| `list[T]` | `T` はスカラー、値クラス、enum、またはリスト |
| `dict[str, T]` | キーは文字列。どちらの実行でも入れた順に回ります |
| `tuple[A, B]` | 形を書き出した組 |
| `@value` クラス | データ。フィールドだけを持ち、同一性を持ちません |
| `@model` クラス | 観測され共有されるもの。参照で辿ります |
| `Enum` | Python の `enum.Enum` |
| `Protocol` | インタフェース。下の[ジェネリクス](#ジェネリクス)を参照 |
| <code>T &#124; None</code> | オプショナル。比較か `match` で受けます |
| `State[T]` | セル |
| `Weak[T]` | 所有しない参照。型検査器には <code>T &#124; None</code> に見えます |

状態の持ち方は `State` と `@store` と `@model` の三つで、その選び方は[言語ツアー](tour.md#状態の持ち方)が案内します。

## 何がどこで検査されるか

三つの答えが三つの時点で返ってきます。
答える問いはそれぞれ違います。

**エディタ。**
型スタブがホイールに同梱されているので、pyright と Pylance は Yokan のアプリを普通の Python として検査します。
`@store` はシングルトンをクラス名に束縛し、`@value` と `@model` はフィールドからコンストラクタを組み立て、`Weak[Node]` は `Node | None` として読めます。
これは Python 自身の型システムが、打ちながら効いている状態です。

**`yokan check app.py`。**
方言の境界を答えます。
この形をコンパイラは受け取れるか、という問いです。
コンパイラを起動しないので答えは一秒ほどで返り、ファイルと行と桁と、代わりに書くものの名前が付いてきます。

```console
$ yokan check app.py
app.py:14:5: not in the dialect — a `list[str]` local starts from a
list literal or another list of the same type
    part = line.split("\t")
           ^
```

**ビルド。**
方言の下にはコンパイラ自身の型検査器があり、前の二つが見られなかった型はここで捕まります。

三つのどれもゲートではありません。
`yokan gate` が比べるのは*振る舞い*です。
同じクリックを開発ビルドと出荷するバイナリの両方で再生して、画面をバイト単位で突き合わせます。
型が答えるのは「コンパイルが通るか」で、ゲートが答えるのは「二つの実行が一致するか」です。

## ジェネリクス

インタフェースは `typing.Protocol` です。
それを引数に取るヘルパーは、ジェネリック関数になります。

```python
class Shape(Protocol):
    def area(self) -> float: ...


@model
class Circle(Shape):
    r: float = 1.0

    def area(self) -> float:
        return self.r * self.r * 3.0


def area_of(s: Shape) -> float:
    return s.area()
```

`yokan translate app.py` を実行すると、何になるかが見えます。

```
fn area_of<P0: Shape>(s: P0) Float {
```

インタフェースで束縛された型パラメータです。
呼び先はコンパイル時に決まります。
呼ばれた型ごとにコンパイラが実体を一つずつ出すので、実行時の探索はなく、型が消えることもありません。

型引数を書くことはありません。
`area_of(circle)` と書けば、呼び出しごとに引数から `P0` が解かれます。

入れ物の型も引数を取ります（`list[T]`、`dict[str, T]`、`State[T]`）。
こちらは書き出します。
要素の型が入れ物の配置そのものだからです。

## 推論しないもの

次のものは推測されずに名前を出して断られます。
理由はどれも同じで、コンパイルされた側が黙って選ぶことになり、その選択が CPython の答えと食い違いうるからです。

- **空の入れ物**には要素型がありません。注釈を付けます。
- **片方の枝でしか代入されないローカル**。
  その枝が走らなかったとき Python は `NameError` を投げるので、if と else の両方で代入すれば読めます。
- **穴に書けないローカル**。
  `f"{x}"` の中の float と bool は、State に持つか `.2f` のように桁を指定するよう求められます。
  Python の `str()` が float に対して答えるものは仕様であって、表示の既定値ではないからです。
- **`T | None` を返すメソッド**。
  store と model のメソッドが返せるのはスカラー、リスト、値クラス、enum です。
  オプショナルの戻り値はまだ方言に入っていません。

理由付きの一覧は、ツアーの末尾の[今できないこと](tour-ship.md#今できないこと)にあります。

## Python が要るとき

方言が受け取れる範囲を超える関数は `@py` を付ければ本物の Python のままになります。
そのとき値は境界を渡ります。
何が渡れるかは [Python との行き来](escapes.md)に書いてあります。
