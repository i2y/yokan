# Python との行き来

`@py` を付けた関数は**本物の Python のまま**です。
方言はその中身をコンパイルしません。
コンパイルするのは*呼び出し*のほうで、中身はどちらの実行でも CPython が動かします。

```python
@py
def stats(xs: list[float]) -> list[float]:
    import numpy as np

    a = np.array(xs)
    return [float(a.mean()), float(a.std())]
```

その境界を渡るものは二つです。
行きの引数と、帰りの答えです。
このページはその二つに何が起きるかの話です。

## 二つの実行は対称ではありません

開発中の `@py` は恒等関数です。
アプリの残りを動かしているのと同じ CPython が、あなたのオブジェクトをそのまま渡して関数を呼びます。
**変換は一切起きません。**
注釈は実行時に読まれもしません。

コンパイルすると、関数のソースはバイナリの中に運ばれ、埋め込みの CPython の上で動きます。
ここでは両側の言葉が違うので、値は行きも帰りも変換されます。
その変換は注釈の通りに行われます。

署名が必須なのはこの非対称のためです。
型検査器のための飾りではなく、コンパイル済みの実行が実装する契約であり、二つの実行が同じ答えを出したことを示すのが `yokan gate` です。

## 渡れるもの

| 書き方 | 渡るもの | Rust 側 |
|---|---|---|
| `int` | 機械の整数 | `i64` |
| `float` | 倍精度浮動小数点数 | `f64` |
| `str` | 文字列 | 行きは `&str`、帰りは `String` |
| `bool` | 真偽値 | `bool` |
| `list[T]` | スカラーのリスト | `Vec<T>` |
| `dict[str, T]` | 文字列キーの表 | `HashMap<String, T>` |
| 値クラス | `frozen=True` の dataclass | 同じフィールドを持つ構造体 |
| <code>T &#124; None</code> | 値、または `None` | `Option<T>` |

`T` はいずれも `int`、`float`、`str`、`bool` です。
この表の外にあるものは黙って形を変えられることはなく、理由付きで断られます。

## 行き

`values` が `State[list[float]]` のとき、アプリが `stats(values())` を呼んだとします。

**開発実行。**
State が持っているリストは Python のリストです。
それがそのまま渡ります。
それだけです。

**コンパイル済みの実行。**
呼び出し側はネイティブのコードで、リストはコンパイラ自身の倍精度の並びです。
Python が見る前に、生成されたクレートがそこから Python のオブジェクトを組み立てます。

- `int` は Python の `int` に、`float` は `float` に、`bool` は `bool` になります
- `str` は Python の `str` になります
- `list[T]` は要素を変換した Python の `list` になります
- `dict[str, T]` は Python の `dict` になります
- 値クラスは、同じフィールド名を持つ `frozen=True` の dataclass の実体になります。この dataclass はまさにこのためにエスケープのモジュールが宣言します
- `None` は `None` のままで、`T | None` のもう一方は値そのものです

関数の中で手にしているのは普通の Python のオブジェクトです。
`xs` はスライスもできれば、numpy に渡すことも、回すこともできるリストです。

## 帰り

戻り値の注釈は逆向きに読まれます。

**開発実行。**
`return` が作ったオブジェクトが、そのままハンドラの受け取る値です。
ここでも変換はありません。

**コンパイル済みの実行。**
返された Python のオブジェクトが、宣言された型に読み戻されます。

- Python の `int` と `float` と `bool` は機械の値になります
- `str` はコンパイラの文字列になります
- `list` は要素ごとに `list[T]` になります
- `dict` は `dict[str, T]` になります
- dataclass の実体はフィールドごとに値クラスになります
- `None` は `T | None` の空のほうになります

注釈に合わないオブジェクトが返ってきたとき（署名が `int` なのに `str` を返した、など）、読み戻しは失敗します。
推測はせず、はっきり失敗します。
[Python が例外を投げたとき](#python-が例外を投げたとき)を参照してください。

## 値クラスの往復

往復をまるごと見ておく価値があるのはここです。
同じ形が二度宣言され、その二つが一致している必要があるからです。

```python
@value
class Reading:
    label: str
    value: float


@py
def normalise(r: Reading) -> Reading:
    return Reading(r.label.strip().lower(), r.value / 100.0)
```

Yokan 側の `Reading` は値クラスです。
フィールドが二つあり、同一性は持ちません。
コンパイルされた側では同じ二つのフィールドを持つ Rust の構造体になり、エスケープのモジュールには対になる宣言が置かれます。

```python
@dataclass(frozen=True)
class Reading:
    label: str
    value: float
```

これで、あなたが書いた Python が `Reading` を組み立てることも読むこともできます。
フィールドは `int`、`float`、`str`、`bool` である必要があります。
リストや別の値クラスを持つ値クラスはまだ渡れず、そのことを言って断ります。

## Python が例外を投げたとき

`try` がなければ、例外は握りつぶされません。
本物のインタプリタが出した本物のトレースバックが表示され、エスケープを呼んだ文は完了しません。
アプリは動き続けます。
止まるのは例外を出したハンドラだけです。

`try` があれば、どちらの実行でも同じ節が走ります。

```python
def compute():
    try:
        n = parse(text())
    except ValueError as e:
        error.set(f"{e}")
        return
    total.set(n)
```

開発実行ではこれは Python 自身の `try` です。
コンパイル済みの実行では、コンパイラが生成した振り分けの関数が埋め込みインタプリタの**中で**例外を捕まえ、どの節が合致したかとメッセージを答えます。
そのため `f"{e}"` は両側で同じバイト列になります。
あなたが書いた節が、その振り分けの材料です。

## task の中で

エスケープには時間のかかるものがあります。
`task` に入れれば、ウィンドウは描き続けます。

```python
def start():
    xs = values()
    task(lambda: stats(xs), on_done=landed, on_progress=moved)
```

コンパイルすると、エスケープは `await` されます。
描画するスレッドではなく、エンジンのスレッドプールの上で動きます。
エスケープの中からは `report(fraction, note)` がこの task の `on_progress` に届きます。

```python
@py
def transcribe(path: str) -> list[str]:
    from yokan import report

    report(0.0, "loading the model")
    ...
```

この import はどちらの実行でも同じ一行です。
開発実行は本物のモジュールを読み込みます。
コンパイル済みのバイナリの埋め込みインタプリタには yokan のパッケージがそもそもないので、生成されたクレートが一関数だけの `yokan` モジュールを置き、同じ経路につなぎます。

これに付いてくる規則が一つあります。
**task の仕事はアプリの状態に触れません。**
UI スレッドの外で走るので、そこから `State` は読めません。
必要な値は task の前に読んで引数で渡し、返ってきた値は `on_done` で書きます。
上の例の `xs = values()` がそれです。

## 渡れないもの

次のものは `yokan check` で断られます。
そのとき、渡れる形がメッセージに並びます。

- **入れ子の入れ物**。
  署名の中の `list[list[int]]` や `dict[str, list[…]]` です。
  行きも帰りも一段までです。
- **値クラスのリスト**。
  要素は一つずつなら渡れますが、そのリストはまだ渡れません。
- **`@model` クラス**。
  model は観測され共有されるもので、同一性はインタプリタの境界を越えて写せるものではありません。
- **`str` 以外をキーにした辞書**。
- **スカラー以外を持つ値クラス**。

## 配るとき

`@py` を持たないアプリは Python を一行も積みません。
一つでも持つアプリは CPython を中に積んで配ります。
`--bundle` はフォルダを、`--onefile` は単一ファイルを、`--app` はそのどちらかを macOS の `.app` にします。
受け取る人は何も入れずに済みます。
詳しくは[検証とリリース](tour-ship.md#リリース)にあります。
